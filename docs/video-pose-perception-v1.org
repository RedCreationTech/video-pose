具体模型被限制在 Adapter 内.

* 3. Detector Adapter

默认适配 Ultralytics YOLO.

使用公开的 Results API:

- boxes.xyxy.
- boxes.conf.
- boxes.cls.
- result.names.

项目训练出的工具检测模型通过 =weights= 注入.

第一阶段类别建议:

- person.
- torque_wrench.
- open_end_wrench.
- component_A.
- 真实项目所需关键工具和工件.

* 4. Operator Tracking

MVP 使用 IoU Tracker, 目标不是解决复杂多人 ReID, 而是稳定单工位操作员身份.

后续接口可替换为:

- ByteTrack.
- BoT-SORT.
- ReID tracker.

上层保持 =TrackedDetection= 不变.

* 5. Pose Adapter

MMPose 1.x 使用:

#+BEGIN_SRC python
from mmpose.apis import init_model, inference_topdown
#+END_SRC

流程:

#+BEGIN_SRC text
Tracked Person BBox
       |
inference_topdown
       |
PoseDataSample.pred_instances
       |
keypoints + keypoint_scores
       |
BODY_KEYPOINT Observation
#+END_SRC

默认使用 COCO 17 点名称.

对于手部操作场景, 后续增加 Hand Pose Adapter, 不应强行把手指关键点混入 COCO Body Pose.

* 6. 依赖策略

核心包不强制依赖 AI 框架.

#+BEGIN_SRC sh
pip install -e '.[yolo,video]'
#+END_SRC

MMPose 环境需要根据 PyTorch/CUDA 选择兼容 MMCV, 因此生产镜像应固定完整版本矩阵.

* 8. 已知边界

当前对象 entity_id 是 frame-local, 工具的跨帧 tracking 尚未实现.

因此当前阶段已经可以:

- 人员稳定跟踪.
- 人体关键点时序.
- 工具类别检测.

但还不能仅靠 Detector 自动形成可靠 =HELD_BY= 关系.

下一阶段需要增加 Human-Object Relation Builder:

#+BEGIN_SRC text
hand keypoint
+
tool bbox
+
temporal stability
+
optional hand pose
      |
      v
HELD_BY / NEAR / TOUCHING
#+END_SRC
