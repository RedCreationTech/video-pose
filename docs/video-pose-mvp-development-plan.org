* 1. MVP 目标

MVP 不是完成通用人体动作理解平台.

MVP 只验证一个明确闭环:

#+BEGIN_SRC text
4 Cameras
   |
Person + Tool + Pose
   |
Multi-view Evidence
   |
5-10 Action Atoms
   |
1 Standard Operation
   |
Rule Engine
   |
Violation + Score + Evidence Replay
#+END_SRC

完成标准:

- 一个真实工位.
- 四路摄像头.
- 一个操作员.
- 一个标准 SOP.
- 5-10 个步骤.
- 至少 3 类故意违规.
- 自动生成结果和证据.
- 能够用固定视频集重复回归.

* 5. Sprint 0: 工程和数据基线

目标:

让团队可以稳定开发和重放视频.

任务:

- 初始化 monorepo.
- Python/Node 版本锁定.
- Docker Compose.
- PostgreSQL/Redis/MinIO.
- CI.
- 代码格式化.
- 单元测试框架.
- 视频 fixture manifest.
- 定义 1 个目标 SOP.
- 明确 3-5 个关键工具.
- 明确 5-10 个 ActionAtom.
- 安装四路摄像头.
- 首次标定.
- 采集第一批标准/错误视频.

交付:

#+BEGIN_SRC text
docker compose up
pytest
web dev server
four-camera replay tool
#+END_SRC

DoD:

- 新开发机 30 分钟内能启动开发环境.
- 4 路录像可同步回放.
- 已有不少于 20 个标注短视频.

* 6. Sprint 1: Video Gateway

目标:

稳定接入四路视频.

任务:

- RTSP discovery/config.
- GStreamer pipeline.
- 硬件解码.
- 时间戳归一化.
- ring buffer.
- reconnect.
- camera health.
- 录像切片.
- Web 低码率 preview.

接口:

#+BEGIN_SRC text
CameraFrameMetadata
CameraHealth
RecorderCommand
EvidenceClipRequest
#+END_SRC

DoD:

- 4 路 1080P@25FPS 连续 8 h.
- 断流自动恢复.
- UI 可看到 4 路预览.
- 能按 timestamp 截取证据片段.

* 7. Sprint 2: Person/Object/Pose

目标:

从视频稳定输出基础视觉事实.

任务:

- person detector.
- operator tracker.
- object/tool detector.
- body pose.
- hand ROI.
- observation schema.
- model manifest.
- visualization overlay.
- offline evaluator.

DoD:

- 在目标工位能稳定跟踪唯一操作员.
- 关键工具达到约定 Precision/Recall.
- wrist/elbow 关键点达到可用水平.
- 每个 Observation 带 model version.

* 8. Sprint 3: Camera Calibration and Fusion

目标:

把四视角对齐到统一时空.

任务:

- intrinsic calibration.
- extrinsic calibration.
- world coordinate.
- zone editor data model.
- clock offset monitor.
- multi-view association.
- 3D wrist/object position MVP.
- occlusion state.

DoD:

- 同一测试点四视角映射一致.
- 3D 位置误差达到测试方案阈值.
- 任一路遮挡时其余视角可继续提供证据.

* 9. Sprint 4: Action Engine

目标:

将视觉事实转换为 ActionEvent.

首批动作:

- REACH.
- GRASP.
- PICK.
- MOVE.
- PLACE.
- ROTATE.
- OPERATE_TOOL.
- INSPECT.

任务:

- feature assembler.
- temporal window.
- heuristic baseline.
- temporal model interface.
- multi-view confidence fusion.
- ActionEvent schema.
- offline replay evaluator.

重要策略:

先做 heuristic/geometry baseline, 再训练 Temporal Model. 这样能更快形成业务闭环并建立可解释基线.

DoD:

- Golden action clips 可自动产生 ActionEvent.
- 每个事件有 start/end/confidence/evidence.
- 不确定时能够输出 UNKNOWN.

* 10. Sprint 5: Rule Engine

目标:

完成 SOP 合规判断.

任务:

- rule DSL.
- parser/validator.
- workflow state machine.
- temporal window.
- sequence constraints.
- object/tool constraints.
- zone constraints.
- three-valued logic.
- violation.
- trace.
- replay.

DoD:

- 一套 5-10 步 SOP 可配置.
- 3 类违规可稳定识别.
- 相同 ActionEvent 重放结果 100% 一致.
- 每个 violation 有规则 trace.

* 11. Sprint 6: Evaluation and Evidence

目标:

让系统输出人能理解的结果.

任务:

- step execution.
- violation summary.
- scoring.
- evidence clip generation.
- four-view synchronized playback.
- pose overlay.
- final report JSON.

DoD:

- 完成 session 后自动生成评分.
- 可以点击违规跳转到对应视频时间点.
- 可查看期望动作, 实际动作和触发规则.

* 12. Sprint 7: Web Console

页面:

1. 工位首页.
2. 四路实时画面.
3. 当前操作步骤.
4. 实时动作事件.
5. 实时违规.
6. Session 历史.
7. Session 复盘.
8. Rule/SOP 配置.
9. Camera/Calibration 状态.
10. Model status.

工业客户端风格:

- 信息密度高.
- 状态颜色稳定.
- 不使用大量动画.
- 关键异常突出.
- 支持大屏和 1080P 工位屏.

* 15. 不建议在 MVP 做的内容

- 通用数百类动作识别.
- 多人复杂交互.
- 云端全量视频实时推理.
- 完整 Kubernetes 平台.
- 自研基础视觉大模型.
- 用 LLM 直接做实时最终合规判定.
- 在没有数据基线时追求 99.9% 指标.

* 16. 数据采集计划

第一轮:

- 5 人.
- 每人 20 个合规 session.
- 每人 10 个错误 session.
- 约 150 个 session.

错误类型至少:

- wrong tool.
- missing step.
- wrong order.
- wrong zone.
- timeout.

第二轮:

加入:

- 遮挡.
- 不同速度.
- 不同工作服.
- 左右手变化.
- 光照变化.

* 21. 关键风险

** 风险 1: 手部和工具遮挡

缓解:

- 侧视角.
- ROI camera optional.
- object relation + pose fusion.
- UNKNOWN.

** 风险 2: 相似工具误识别

缓解:

- 训练专用 detector.
- 工具架固定位置.
- marker/颜色辅助.
- 二次确认.

** 风险 3: 四路时间不同步

缓解:

- NTP/PTP.
- offset monitor.
- fusion tolerance window.

** 风险 4: 动作定义模糊

缓解:

先建立 SOP 领域模型和动作词典, 再训练模型.

** 风险 5: 现场指标无法达到

缓解:

- 先固定单工位.
- 收集 hard cases.
- 把不可观测情况显式归类.
- 不使用平均指标掩盖关键违规漏检.
