* 1. Verification Objective

目标不是证明某一个模型 mAP 很高, 而是证明完整 Session 在真实工业场景中能够:

- 稳定采集四路视频.
- 保持时间同步和可观测性.
- 识别关键动作和工具.
- 正确执行 SOP 规则.
- 对违规产生证据.
- 对不可观测/系统故障不误报 PASS.
- 保存不可抵赖 Audit.
- 在数据库/进程故障后可恢复.
- 7x24 运行不出现资源和状态泄漏.

最终测试单位是 Operation Session, 不是单帧.

* 14. Audit Verification

Audit 是灾难恢复事实源.

每个 Session 验证:

#+BEGIN_SRC text
metadata.json
updates.jsonl
reviews.jsonl
final.json
recovery.json optional
#+END_SRC

测试:

- append success.
- append failure.
- writable probe.
- DEGRADED -> READY recovery.
- cumulative error counter.
- final.json failure.
- SYSTEM_QUALITY-AUDIT.
- Session returned passed=false after audit failure.

Audit 故障不能被 SQL 成功掩盖.

* 15. Persistence and Reconciliation Verification

SQL 是 Query Store.

测试:

- normal dual-write.
- DB unavailable during update.
- current Session continues with JSONL.
- connectivity status DEGRADED.
- probe recovers connectivity to READY.
- reconciliation stays DIRTY.
- Audit -> SQL reconcile.
- consistency verification after repair.
- second reconcile idempotently SKIPPED.
- review state restored.
- final status/score/passed restored.

生产 Gate:

#+BEGIN_SRC text
connectivity = READY
reconciliation = READY
#+END_SRC

两者必须同时成立才能开始新正式 Session.

* 16. Crash Recovery Verification

构造:

#+BEGIN_SRC text
metadata exists
updates exist
final missing
#+END_SRC

验证:

- listed as incomplete.
- normal reconciliation keeps DIRTY.
- explicit recovery required.
- recovery.json created.
- prior known step/violation state retained.
- SYSTEM-QUALITY-RECOVERY appended.
- status = ABORTED.
- score = 0.
- passed = false.
- subsequent reconciliation returns READY.

禁止把 crash Session 自动补成 COMPLETED.
