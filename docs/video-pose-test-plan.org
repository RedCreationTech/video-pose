#+TITLE: Video Pose Verification and Validation Plan
#+SUBTITLE: 多摄像头动作规范检测系统测试与验收方案
#+AUTHOR: RedCreationTech
#+DATE: 2026-09-20
#+OPTIONS: toc:3 num:t

* 1. 测试目标

本测试计划验证系统是否能够在真实工业环境中持续, 稳定, 可解释地判断人员操作规范性.

测试不能只看单模型 mAP. 最终必须验证端到端业务结果.

测试层级:

#+BEGIN_SRC text
L0 Camera / Infrastructure
L1 Perception Model
L2 Pose and Multi-view Fusion
L3 Action Recognition
L4 Rule Engine
L5 End-to-End Operation
L6 Reliability / Performance / Security
L7 Field Acceptance
#+END_SRC

* 2. 核心验收思想

建立三套相互分离的数据集:

- Train Set.
- Validation Set.
- Acceptance Test Set.

Acceptance Test Set 在模型和阈值冻结前不得用于调参.

测试人员和训练人员应尽量分离.

* 3. Ground Truth

每条验收视频需要人工标注:

- session start/end.
- operator id, 使用匿名测试编号.
- action interval.
- object/tool.
- step start/end.
- violation type.
- visibility/occlusion.
- camera quality.
- final compliance result.

关键违规建议双人独立标注, 有分歧时仲裁.

* 4. 测试数据矩阵

至少覆盖以下维度.

** 4.1 人员

- 身高差异.
- 体型差异.
- 左撇子/右撇子.
- 熟练人员/新手.
- 不同工作服.
- 戴手套/不戴手套.

** 4.2 环境

- 正常照明.
- 偏暗.
- 局部强光.
- 背光.
- 设备反光.
- 背景人员经过.
- 工位轻微变化.

** 4.3 动作

- 标准速度.
- 快速操作.
- 慢速操作.
- 中途暂停.
- 回退重做.
- 左右手交换.
- 连续重复动作.

** 4.4 遮挡

- 手被身体遮挡.
- 工具被手遮挡.
- 工件被设备遮挡.
- 单摄像头完全不可见.
- 两个视角同时部分遮挡.

* 5. Camera Test

测试项:

- RTSP 连接.
- 自动重连.
- 分辨率.
- 实际 FPS.
- dropped frame.
- 时间戳单调性.
- clock offset.
- 网络抖动.
- 断网恢复.

验收建议:

| 指标 | MVP 目标 |
| 连续运行 | >= 72 h |
| 自动重连成功率 | 100% in test cases |
| 正常网络丢帧率 | < 1% |
| 多相机同步误差 | < 20 ms, NTP 方案 |
| 时间戳回退 | 0 |

* 6. Calibration Test

指标:

- reprojection error.
- 3D point consistency.
- zone boundary accuracy.
- calibration drift.

测试方法:

1. 在已知位置放置标定点.
2. 四视角分别检测.
3. 重建世界坐标.
4. 与物理测量值比较.

建议目标:

| 指标 | 目标 |
| 平均 3D 定位误差 | < 30 mm, MVP |
| 95 分位误差 | < 60 mm |
| Zone 边界判定 | >= 95% |

最终阈值按动作尺度调整.

* 7. Person Detection Test

指标:

- Precision.
- Recall.
- mAP50.
- ID switch.
- track loss.

工业应用更关注目标操作员 Recall 和稳定 tracking.

建议:

| 指标 | MVP 目标 |
| Operator Recall | >= 98% |
| Precision | >= 97% |
| 关键动作期间 track loss | < 1% time |

* 8. Pose Test

2D:

- PCK.
- OKS/mAP.
- wrist/elbow/shoulder 分项.

3D:

- MPJPE.
- wrist 位置误差.
- temporal jitter.

手腕通常是动作识别关键点, 不应只看全身平均值.

* 9. Object and Tool Test

每个业务关键工具单独统计:

#+BEGIN_SRC text
precision
recall
confusion matrix
small-object recall
occluded recall
#+END_SRC

不能只报告所有类别平均 mAP.

例如 torque_wrench 与 open_end_wrench 如果容易混淆, 必须单独建立错误矩阵.

* 10. Action Recognition Test

每个 ActionAtom 统计:

- Precision.
- Recall.
- F1.
- start boundary error.
- end boundary error.
- confusion matrix.

MVP 建议关键动作:

#+BEGIN_SRC text
PICK
PLACE
MOVE
INSERT
ROTATE
OPERATE_TOOL
INSPECT
ENTER_ZONE
LEAVE_ZONE
#+END_SRC

建议目标:

| 指标 | 关键动作 |
| Precision | >= 95% |
| Recall | >= 93% |
| F1 | >= 94% |
| 动作边界 MAE | < 300 ms |

真实目标根据 PoC 数据再冻结.

* 11. Multi-view Fusion Test

构造:

- front unavailable.
- rear unavailable.
- left unavailable.
- right unavailable.
- one view occluded.
- two views partially occluded.

比较:

#+BEGIN_SRC text
single-view baseline
vs
four-view fusion
#+END_SRC

验收必须证明多视角带来实际提升, 否则复杂度没有价值.

* 12. Rule Engine Test

规则测试不依赖视频, 使用确定性 ActionEvent fixture.

覆盖:

- 顺序正确.
- 顺序错误.
- 漏步骤.
- 错工具.
- 错工件.
- 超时.
- 区域错误.
- safety violation.
- UNKNOWN.
- 重复事件.
- 乱序事件.
- session replay.

目标:

#+BEGIN_SRC text
Rule semantic test pass = 100%
Replay determinism = 100%
Duplicate violation due to replay = 0
#+END_SRC

* 13. End-to-End Test

最终测试单位不是 frame, 而是完整 operation session.

每次 session 输出:

- step sequence.
- detected actions.
- violations.
- final score.
- pass/fail.
- evidence.

最终业务指标:

** 13.1 Violation Detection Recall

#+BEGIN_SRC text
TP / (TP + FN)
#+END_SRC

** 13.2 False Alarm Rate

#+BEGIN_SRC text
FP / total compliant sessions
#+END_SRC

** 13.3 Session Classification

- compliant session accuracy.
- non-compliant session recall.
- critical violation recall.

建议第一阶段验收目标:

| 指标 | 目标 |
| 关键违规 Recall | >= 95% |
| 一般违规 Recall | >= 90% |
| 违规 Precision | >= 90% |
| 合规 session 误报率 | <= 5% |
| CRITICAL 漏报 | 在已定义可观测范围内趋近 0, 单独报告 |

不能承诺视觉系统在完全遮挡或不可观测情况下零漏报. 必须明确可观测边界.

* 14. Negative Test

刻意制造:

- 拿错工具.
- 跳过一步.
- 先做后一步.
- 工具放错区域.
- 一只手遮挡.
- 用类似外形工具替代.
- 做到一半停止.
- 两次重复同一步骤.
- 非操作人员进入画面.
- 操作员短暂离开.

* 15. Boundary Test

- 动作持续时间刚好等于 min.
- 刚好低于 min.
- 刚好等于 max.
- 刚好高于 max.
- confidence 恰好位于阈值.
- 手在 zone 边界.
- 工具在两个相邻 zone 边界.

* 16. Long Running Test

测试:

- 8 h.
- 24 h.
- 72 h.
- 连续多 session.

监测:

- RAM.
- GPU memory.
- file descriptor.
- thread count.
- queue lag.
- latency.
- disk.
- video reconnect.

成功标准:

- 无持续内存增长趋势.
- 无 GPU memory leak.
- latency 不随运行时间明显恶化.
- session 数据不串扰.

* 17. Performance Test

负载模型:

#+BEGIN_SRC text
4 cameras
1080P
25 FPS each
1 active operator
20 object classes
10 action classes
200 active rules
#+END_SRC

测量:

- decode latency.
- perception latency.
- pose latency.
- action latency.
- rule latency.
- WebSocket latency.
- end-to-end latency.

目标示例:

| 指标 | MVP |
| 实时事件端到端 P95 | < 500 ms |
| Rule Engine P95 | < 20 ms |
| UI 推送 P95 | < 200 ms |
| GPU memory | 不超过选定硬件稳定上限 |
| dropped frame | < 1% normal load |

* 18. Degradation Test

模拟:

- 1 camera offline.
- 2 cameras offline.
- GPU overload.
- model unavailable.
- Redis unavailable.
- PostgreSQL unavailable.
- center network unavailable.
- MinIO temporarily unavailable.

检查系统是否:

- 明确展示 DEGRADED.
- 保留未发送数据.
- 不把未知误报为合规.
- 恢复后正确补传.

* 19. Evidence Test

对每个 violation 检查:

- 视频片段存在.
- 时间点正确.
- camera 对应正确.
- 前后缓冲足够.
- overlay 与原视频同步.
- sha256 正确.
- 权限控制有效.

* 20. Security Test

- 未授权 API.
- 越权访问他人视频.
- expired token.
- signed URL 过期.
- RTSP 凭据泄露检查.
- container privilege.
- dependency vulnerability.
- audit trail.

* 21. Privacy Test

验证:

- 删除策略.
- 导出权限.
- 人员匿名化.
- 原始视频保留期.
- 删除后对象存储同步删除.
- 审计日志保留.

* 22. Model Regression Test

每个模型新版本必须与基准版本比较:

#+BEGIN_SRC text
accuracy
latency
GPU memory
critical classes
occluded scenes
field data
#+END_SRC

禁止只看总体平均指标后直接升级.

* 23. Rule Regression Test

每个 rule_set 发布前自动运行 fixture.

结果保存:

- rule_set version.
- test case version.
- pass/fail.
- expected decision.
- actual decision.

* 26. Golden Replay Set

建立固定 Golden Set.

要求:

- 20-50 个短 session 起步.
- 包含所有关键违规.
- 每个版本发布自动重放.
- 结果与 expected JSON 比较.
- 模型更新允许数值置信度变化, 但关键业务决策不得无解释漂移.

* 27. 现场验收

第一阶段建议至少:

- 3-5 名操作人员.
- 每人 20 个合规 session.
- 每人 10 个故意违规 session.
- 总计 >= 150 个 session.

如果实际工艺动作复杂, 扩大样本.

现场验收报告至少包含:

- 测试环境.
- 摄像头配置.
- 模型版本.
- 规则版本.
- 数据分布.
- 指标.
- 错误案例.
- 不可观测案例.
- 剩余风险.

* 28. Go/No-Go Gate

MVP 可进入现场试运行的条件:

- Camera 72 h 稳定测试通过.
- Golden Replay 100% 执行通过.
- 关键违规 Recall 达到约定阈值.
- 合规误报率达到约定阈值.
- evidence 完整.
- 无 P1 安全和数据丢失缺陷.
- 所有 UNKNOWN 场景 UI 能明确展示.
- 版本和规则可回滚.
