* 1. 目标

生产实时采集允许配置:

#+BEGIN_SRC yaml
live:
  backend: gstreamer-opencv
  rtsp_transport: tcp
  latency_ms: 100
  appsink_max_buffers: 1
  appsink_drop: true
  appsink_sync: false
#+END_SRC

* 2. 默认 GStreamer Pipeline

H264:

#+BEGIN_SRC text
rtspsrc
 -> rtph264depay
 -> h264parse
 -> avdec_h264
 -> videoconvert
 -> BGR
 -> appsink
#+END_SRC

H265 对应 =rtph265depay / h265parse / avdec_h265=.

* 3. Backpressure

appsink 默认限制为:

#+BEGIN_SRC text
max-buffers=1
drop=true
sync=false
#+END_SRC

目的:

- 不积累旧视频帧.
- 不让流线程因应用处理慢而长期阻塞.
- 与上层 LiveAnalysisRuntime 的 drop-oldest 策略保持一致.

* 4. Decoder Override

现场如果 OpenCV/GStreamer 构建支持硬件解码, 可指定:

#+BEGIN_SRC yaml
decoder_element: nvh264dec
#+END_SRC

具体硬件元素需要根据 NVIDIA/Intel/AMD/Jetson 环境实测.

* 5. Doctor

当 =backend=gstreamer-opencv= 时, =video-pose-doctor= 会检查:

#+BEGIN_SRC text
OpenCV build information -> GStreamer: YES
#+END_SRC

如果当前 OpenCV wheel 不带 GStreamer, Doctor 直接 FAIL, 不允许带病进入正式 Session.

* 6. 生产后续

更完整的 Linux 边缘版本可以进一步切换到原生 GStreamer appsink/PyGObject, 直接读取 buffer PTS/RTP 时间戳, 减少 OpenCV 中间层.
