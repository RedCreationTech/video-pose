* 1. 文档目的

本文描述 Video Pose 当前生产实现的系统边界, C4 Context, Container, Component, Deployment, 关键数据流和故障语义.

当前基线:

#+BEGIN_SRC text
Video Pose 0.42
#+END_SRC

本系统不是一个通用视频理解平台. 它面向固定工业工位, 通过前后左右四路视频持续观测操作过程, 将视觉事实转换为 ActionEvent, 再使用版本化规则判断动作顺序, 工具, 区域, 时间和操作规范性.

核心原则:

- AI 负责识别事实, 最终合规由规则引擎判断.
- 四路摄像头必须进入统一时间轴.
- UNKNOWN 和 SYSTEM_QUALITY 是正式业务状态.
- 不可观测不能被解释为合规.
- Violation 必须能够回到证据和规则 trace.
- Immutable Audit 是灾难恢复事实源.
- PostgreSQL 是可重建的 Query Store.
- 正式 Session 只有在 Readiness Gate 通过后才能启动.
- 运行中观测质量下降必须影响最终 Session 结论.
- Capture timestamp source 必须显式记录和审计.

* 2. 目标与非目标

** 2.1 当前目标

- 单工位.
- 单主要操作员.
- 前, 后, 左, 右四路摄像头.
- 5-20 个标准作业步骤.
- 人员, 工具, 工件, 区域和关键姿态识别.
- 顺序, 时间, 工具, 区域, 缺失步骤和系统质量违规.
- 实时 Session 评分与 PASS/FAIL.
- 四路违规证据.
- 人工复核.
- 7x24 Edge 运行.
- 可恢复 Audit/SQL 数据链.
- 可重复 Golden Replay, Fault Replay 和 Managed Soak.

** 2.2 当前不承诺

- 任意开放世界动作理解.
- 完全无盲区视觉.
- 完全依靠单一大模型直接判断工艺合规.
- 把当前 Edge Runtime 强制拆成大量微服务.
- 在无独立现场验收集时承诺固定准确率.
- 在完全遮挡场景下承诺零漏报.

- 四路视频需要低延迟共享内存.
- YOLO/RTMPose 模型需要跨 Session 常驻 GPU.
- Edge 单工位的故障域和部署复杂度需要可控.

* 6. Capture and Timestamp Architecture

** 6.1 Capture Backends

| Backend | Purpose |
| opencv | 开发和兼容模式 |
| gstreamer-opencv | 显式 GStreamer pipeline, OpenCV 读取 |
| gstreamer-native | GstAppSink 原生读取, 可使用 PTS/RFC7273 reference timestamp |

** 6.2 Timestamp Sources

#+BEGIN_SRC text
arrival
  local monotonic arrival time

pts
  GstBuffer PTS, rebased to a monotonic process timeline

reference
  GstReferenceTimestampMeta, intended for shared RFC7273/NTP/PTP reference
#+END_SRC

重要约束:

- PTS 不等于绝对源时钟.
- reference 模式缺少 ReferenceTimestampMeta 时直接失败.
- 系统不允许在同一路流中静默混用时间基准.
- Camera Health 的 freshness 始终使用本机 monotonic arrival time.
- Multi-view Synchronizer 使用 source timestamp + configured clock_offset_ms.
- Session metadata 固化 capture_backend 和 timestamp_source.

* 8. Persistent Runtime Model

摄像头和重模型的生命周期长于 Session.

#+BEGIN_SRC text
Edge process
 |
 +-- PersistentCameraHub -----------------------------+
 |                                                   |
 +-- PersistentModelPool                             |
 |    YOLO / Pose                                    |
 |                                                   |
 +--> Session A                                      |
 |      SessionAnalysisRuntime                       |
 |      RealtimeRuleSession                          |
 |                                                   |
 +--> Session B                                      |
 |      fresh rule/action state                      |
 |                                                   |
 +--> Session C                                      |
        fresh rule/action state
#+END_SRC

收益:

- Session 开始不重新建立 4 路 RTSP.
- Session 开始不重新加载 YOLO/RTMPose.
- Rule/Action state 每个 Session 重新创建, 避免跨 Session 串扰.
- Managed Soak 可以主动反复 start/stop Session 验证状态隔离.

* 10. Rule and Evaluation Architecture

** 10.1 Deterministic Rule Session

Realtime 和 Replay 共用同一 RuleEngine.

主要违规:

- ORDER.
- MISSING.
- TEMPORAL.
- TIMEOUT.
- wrong tool/object.
- wrong source/target zone.
- spatial violations.
- SYSTEM_QUALITY.

** 10.2 Pass/Fail

MAJOR 或 CRITICAL violation 会让 Session =passed=false=.

Score 由规则严重度 penalty 计算.

系统质量失效不能被解释为"没有违规".

* 11. In-session Quality Guard

Session Start 健康不代表整个 Session 永远健康.

运行中持续监测:

- camera state and freshness.
- sync stall/miss/skew/drift.
- processing error delta.
- processing FrameSet drop ratio.
- Evidence Worker error delta.
- Evidence Worker drop ratio.
- Evidence over-capacity.
- immutable Audit write health.

持续故障经过 grace 后生成:

#+BEGIN_SRC text
step     = SYSTEM
type     = SYSTEM_QUALITY
severity = CRITICAL
#+END_SRC

典型 Rule ID:

#+BEGIN_SRC text
SYSTEM-QUALITY-CAMERA-CAM-FRONT
SYSTEM-QUALITY-SYNC
SYSTEM-QUALITY-PROCESSING
SYSTEM-QUALITY-EVIDENCE
SYSTEM-QUALITY-AUDIT
SYSTEM-QUALITY-RECOVERY
#+END_SRC

故障恢复后 Monitor 重新武装. 后续再次发生会形成新的 incident.

* 16. Persistence Resilience

** 16.1 Connectivity Health

#+BEGIN_SRC text
READY
DEGRADED
#+END_SRC

累计保留 read/write error counters.

连接恢复后 probe 可以重新变为 READY.

** 16.2 Reconciliation Health

#+BEGIN_SRC text
NEVER
READY
DIRTY
RUNNING
DEGRADED
#+END_SRC

连接 READY 不等于历史数据完整.

任意 SQL write failure 会把 reconciliation 标成 DIRTY.

只有 Audit -> SQL 对账成功并且不存在未完成 Audit Session 时才能回 READY.

* 17. Audit -> SQL Reconciliation

对 finalized Session 比较:

- Action event_id set.
- Violation stable identity set.
- Step code set.
- Review state.
- final status.
- final score.
- final passed.

不一致时:

#+BEGIN_SRC text
delete SQL Session
      |
replay metadata
      |
replay updates
      |
replay final
      |
replay reviews
      |
verify again
#+END_SRC

该过程是幂等的.

一致 Session 直接 SKIPPED.

* 18. Crash Recovery

进程/主机在 Session 中途崩溃时:

#+BEGIN_SRC text
metadata.json exists
updates.jsonl exists
final.json missing
#+END_SRC

这类 Session 不能被静默删除或当成 COMPLETED.

受控恢复:

- 保留已知 Step 状态.
- 保留已知 Violation.
- 写 recovery.json.
- 追加 CRITICAL SYSTEM-QUALITY-RECOVERY.
- score = 0.
- passed = false.
- final status = ABORTED.
- 再执行 Audit -> SQL reconciliation.

* 19. Session Start Readiness Gate

正式 Session 启动前, 生产模板检查:

- PersistentCameraHub running.
- PersistentModelPool loaded.
- enabled cameras ONLINE.
- sync warmup samples.
- sync miss ratio.
- P99 skew.
- clock drift.
- Evidence capacity.
- Evidence worker errors.
- Audit probe.
- PostgreSQL connectivity.
- reconciliation READY.
- filesystem free ratio and free GB.
- runtime assets exist.
- optional calibration health.

Readiness 失败返回结构化检查项.

#+BEGIN_SRC text
GET /health/live
GET /health/ready
GET /api/v1/sessions/readiness
#+END_SRC

Liveness 与 Session readiness 被明确分离.

* 26. Architecture Decisions

** ADR-001: Rules Own Compliance Decision

视觉模型输出事实, 规则决定业务结论.

** ADR-002: Replay and Realtime Share Rule Semantics

Replay 与实时使用同一 RuleEngine, 以确保规则可回归.

** ADR-003: Current Edge Uses One Process with Logical Components

当前单工位不强制微服务拆分. 优先共享内存, GPU 模型复用和低运维复杂度.

** ADR-004: Persistent Cameras and Models, Session-scoped State

RTSP 和重模型常驻. Action/Rule Session 状态每次重建.

** ADR-005: Explicit Timestamp Semantics

arrival, PTS, reference 不混用. 时间基准进入 Audit fingerprint.

** ADR-006: Evidence First

每个违规必须能够回到多视角证据.

** ADR-007: Immutable Audit Is Recovery Source

PostgreSQL 可从 Audit 重建.

** ADR-008: Query Store Connectivity and Completeness Are Separate

READY connectivity 不能代表 reconciliation READY.

** ADR-009: Observability Failure Invalidates Compliance

持续 camera/sync/processing/evidence/audit 故障形成 SYSTEM_QUALITY.

** ADR-010: Formal Session Requires Readiness Gate

进程存活不等于可以开始正式考核.

** ADR-011: Crash Recovery Is Explicit ABORTED

缺失 final.json 的 Session 不能自动推断为 COMPLETED.

* 27. Current Boundary vs Future Platform

当前已实现重点是单 Edge Node 的可靠业务闭环.

未来中心平台可以增加:

- 多 Edge 设备注册.
- 配置和规则集中发布.
- 模型制品仓库.
- 企业级报表.
- Evidence 长期对象存储.
- Edge outbox/sync.
- SSO/IdP.
- OpenTelemetry aggregation.
- multi-site operations.

这些能力不应反过来增加单工位实时链路的硬依赖.
