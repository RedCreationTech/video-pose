#+SUBTITLE: Immutable JSONL Write Failures as Session Quality Failures
#+AUTHOR: RedCreationTech
#+DATE: 2026-09-21

* 1. Why

JSONL audit is the disaster-recovery fact source.

If Action/Violation decisions continue while immutable audit cannot be written, a PASS result is not trustworthy.

* 2. Audit health

=SessionAuditWriter= now tracks:

- status READY/DEGRADED.
- cumulative write_errors_total.
- last_error.
- last_success_at.

A writable probe can recover DEGRADED back to READY while keeping the cumulative error counter.

* 3. In-session guard

Production Session quality enables:

#+BEGIN_SRC yaml
monitor_audit: true
audit_grace_ms: 0
max_audit_error_delta: 0
#+END_SRC

Any new audit write failure in the Session becomes:

#+BEGIN_SRC text
SYSTEM-QUALITY-AUDIT
severity = CRITICAL
#+END_SRC

Counters are Session-local deltas, so a historical write error does not poison a later Session after storage is repaired.

* 4. Controller failure semantics

Routine update audit failures are recorded by AuditHealth but do not stop SQL/WebSocket/Evidence processing.

Before Session stop, Controller probes Audit and performs one synchronous quality poll so a current write failure enters the final rule result.

If writing =final.json= itself fails after that probe, Controller still:

- adds a CRITICAL Audit quality violation to the returned final result.
- attempts to persist the quality violation and final result to SQL.
- publishes the quality update to realtime clients.
- can still schedule Evidence.

The unavailable immutable file is not hidden, but the Session lifecycle can finish deterministically with =passed=false=.

* 5. Readiness

Production readiness sets =block_audit_degraded=true=.

A new formal Session is blocked until an audit probe succeeds.

* 6. Prometheus and Soak

#+BEGIN_SRC text
video_pose_audit_ready
video_pose_audit_write_errors_total
#+END_SRC

Managed Soak fails on any Audit write error by default.
